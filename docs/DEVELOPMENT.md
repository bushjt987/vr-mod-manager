# Development

## Getting running

```bash
npm install
npm run dev
```

Windows only in practice — detection reads the Windows registry and probes `<drive>:\XboxGames`.

If `npm run dev` fails with `Error: Electron uninstall`, the Electron binary did not download during
install:

```bash
node node_modules/electron/install.js
```

## Scripts

| Script | What it does | Touches the network? | Writes anything? |
|---|---|---|---|
| `npm run dev` | electron-vite dev server with HMR for the renderer | yes | app state only |
| `npm run typecheck` | both tsconfig projects, no emit | no | no |
| `npm run build` | typecheck, then build main/preload/renderer into `out/` | no | `out/` |
| `npm run dist` | build, then an NSIS x64 installer into `release/` | no | `out/`, `release/` |
| `npm run e2e` | real install/uninstall cycle against a throwaway game folder | yes | temp dirs only |
| `npm run scan` | read-only report of games and already-installed mods on this PC | no | nothing |
| `npm run check-sources` | resolves every GitHub-backed mod through the app's own resolver | yes | nothing |
| `npm run docs:table` | rewrites the README catalog table from the catalog | no | `README.md` |

Two more scripts exist without npm aliases, built through `scripts/identify.vite.config.ts`:
`verify-identify.ts` checks checksum identification against the real installs on this PC (read-only,
but it downloads release archives into the normal cache).

### `npm run e2e`

It really hits GitHub and really writes files — that is the point. It never touches a detected game:
the game root is a temp directory seeded to look like a Halo install, with a planted
`openvr_api.dll` so backup and restore are actually exercised. It covers install, reinstall-over-the-
top (the update path), uninstall, and a separate `.7z` round trip through the Overlord entry, because
7-Zip extraction goes through an external binary and can fail independently of adm-zip.

The final assertion is the valuable one: the game folder is left exactly as it was found. That is what
caught `ensureDir` recording only the deepest directory level and leaving an empty `VR/` behind.

### `npm run check-sources`

Mod authors rename release assets and occasionally delete repositories. This exercises the real
resolver rather than a second implementation of it, so a pass means the app can genuinely download
every mod. Run it before shipping and whenever a user reports a failed install. It has already caught
an asset rename (MCCVR) and a deleted repository (`KozGit/DOOM-3-BFG-VR`, repointed to a fork).

## TypeScript setup

Three configs, because main and renderer target different runtimes:

| Config | Covers | Module system | Aliases |
|---|---|---|---|
| `tsconfig.node.json` | `src/main`, `src/preload`, `src/shared`, the vite config | NodeNext | `@shared/*` |
| `tsconfig.web.json` | `src/renderer/src`, `src/shared` | bundler | `@/*`, `@renderer/*`, `@shared/*` |
| `tsconfig.json` | solution-style; references both | — | `@/*` **for the shadcn CLI's benefit** |

That last one is not decoration. The shadcn CLI reads `compilerOptions.paths` from `tsconfig.json`
only; without the alias there it writes components into a literal `@` folder and rewrites their `cn`
import to a bare `"cn"` specifier, which pulls an unrelated npm package into the dependencies. See
[UI.md](UI.md#if-you-run-npx-shadcn-add-again).

**`scripts/` is covered by neither config**, so `npm run typecheck` does not check it. A broken string
literal in `e2e-install.ts` once got caught by the vite build instead of by the typechecker. Worth
fixing — see [ROADMAP.md](ROADMAP.md).

## Building the dev scripts

Each script in `scripts/` has its own small vite config that bundles it as an ESM file into
`out/e2e/`, reusing the real main-process modules so the harness exercises shipping code rather than a
reimplementation.

Every one of those configs sets **`emptyOutDir: false`**. They share `out/e2e` with distinct
filenames, and with the default `true` each build wiped the others — which silently emptied the README
catalog table, because `catalog-table.mjs` had been deleted by a previous build when the splice ran.
If you add another script config, keep that flag.

`npm run docs:table` **writes `README.md` itself** rather than printing a table to paste. The table
drifted twice from being regenerated by hand, so the safe version is the one nobody has to remember to
copy. It needs the `<!-- catalog:start -->` / `<!-- catalog:end -->` markers to stay in the README, and
it reads `README.md` relative to the working directory — run it from the repo root.

## Bundling and packaging

- `adm-zip`, `7zip-min` and `7zip-bin` are **external** to the main bundle and listed in
  electron-builder's `files`. `7zip-bin` ships a real executable, so it is also in `asarUnpack` —
  a binary inside an asar cannot run.
- `npmRebuild: false`: nothing here is a native module needing a rebuild.
- NSIS, x64, non-oneClick, per-user, install directory changeable.
- `resources/` is electron-builder's `buildResources` directory and is currently **empty**, so the app
  ships with the default Electron icon.

## Line endings

`.gitattributes` stores text as LF in the repo and checks out native on Windows, with `eol=lf` pinned
for the file types tools read rather than hands edit (`.ts`, `.tsx`, `.css`, `.json`, `.md`, `.html`).
Binaries are marked `binary`. Without this, a checkout on another OS shows every file as modified.

## Editing gotchas

Collected the hard way in this codebase:

- **Catalog factory calls are not object literals.** `reframework(...)` entries do not look like the
  surrounding `{ ... }` blocks to a line-range edit. Deleting a neighbouring mod once took all five
  with it. After editing the catalog, run `npm run docs:table` and read the printed count.
- **Escaped backslashes do not survive careless editing.** `archive.ts` builds the Windows separator
  as `String.fromCharCode(92)` on purpose, so no escaped backslash literal has to survive. Prefer
  structured edits over shell heredocs for TypeScript.
- **Hiding output hides damage.** A `grep`-filtered verification once concealed that five catalog
  entries had been deleted, and a `>/dev/null` concealed that the table generator's bundle was
  missing. Read the whole output of a check.
